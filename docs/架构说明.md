# 模块架构说明 · 高内聚低耦合

「赓续血脉・数绘红旅」shanhexu 为纯静态站点，采用**原生浏览器 ES Modules**，无框架、无打包工具、无后端。本文档说明其模块架构与工程约束。

## 一、概览

- **39 个 ES Module**，单一入口 `js/app.js`（boot 编排：布局注入 → 事件委托 → 页面路由 → 数据加载 → 功能初始化）
- **依赖单向无环**：已程序化校验，全图 0 依赖环
- **UI / 逻辑 / 数据三层分离**：渲染器只管出 HTML 字符串、纯逻辑模块不碰 DOM、数据层集中管理
- **事件委托替代内联处理**：全站交互走 `data-action` 属性 + 单一派发中枢

## 二、依赖规则（新增模块必读）

```
叶子（零 import） → 数据/共享层 → 功能模块 → 入口(app.js)
```

1. 新模块只能 import **叶子或上游模块**，禁止 import `app.js`（唯一入口不应被反向依赖）
2. 一文件一导出 `initX()`；文件头注释块写明「职责 / 约束 / 依赖」
3. 模块名**小写连字符**（如 `cz-stations.js`）——缓存破击工具链 `bump-version.js` 的正则只匹配单段 `./x.js` 相对导入，这是平铺布局的硬约束
4. 纯逻辑模块（`data.js` / `chat-engine.js` / `venue-store.js`）不写 DOM，可在无 DOM 环境测试

## 三、分层与模块清单

| 层 | 模块 | 职责 |
|---|---|---|
| **叶子**（零依赖，13个） | `utils` `icons` `focus-trap` `red-history` `quiz-data` `chat-knowledge` `heatmap-data` `cz-stations` `cz-content` `cz-stamps` `entrance-animation` `hero-carousel` 等 | 纯工具/图标/数据/几何，可被任何人依赖 |
| **共享层** | `ui`（UI 原子）`data`（JSON 缓存/合并）`venue-store`（场馆门面）`renderers`（HTML 渲染）`modals` `favorites` `music` `darkmode` `mobile-nav` `layout-loader` `action-delegate` | 跨页面复用 |
| **页面控制器** | `pages`（6 页面初始化 + 点赞/留言/分页） | 装配各页 |
| **功能模块** | 长征 `longmarch` + `cz-*`（9个）；AI `chat` + `chat-engine` + `chat-knowledge`；问答 `quiz` + `quiz-data`；首页 `homepage` `heatmap` `heatmap-data` `timeline` `cardgen` | 各自闭环 |
| **入口** | `app.js` `version.js` | 编排与版本单源 |

## 四、关键机制

- **data-action 委托**：`action-delegate.js` 单一 switch 派发，新增交互 = 元素加 `data-action` + 在该 switch 加 case（`tests/data-action.test.js` 强制闭环）
- **单一权威缓存**：`data.js` 是场馆/数据唯一缓存，`venue-store.js` 只做薄门面，避免双缓存分叉
- **模板运行时注入**：`templates/` 的 header/footer 经 `layout-loader` 注入，路径用 `{{BASE}}` 占位符
- **缓存破击**：`js/version.js` 的 `ASSET_VERSION` 是唯一版本源，`npm run bump` 同步全站 `?v=`（含 js/ 相对 import）；**工具链按 js/ 平铺设计，不要拆子目录**（见第六节）
- **弹窗统一**：focus-trap 计数锁 + 遮罩点击/ Esc 关闭，避免滚动锁失衡

## 五、高内聚低耦合实测（程序化分析）

| 指标 | 数值 | 说明 |
|---|---|---|
| 依赖环 | **0** | 单向无环 ✓ |
| 总依赖边 / 平均扇出 | 109 / 2.8 | 非意大利面 |
| 高扇入叶子 | `utils(19)` `icons(16)` `ui(13)` | 稳定底座 |
| 高扇出编排 | `app.js(13)` `longmarch(12)` `action-delegate(9)` `pages(9)` | 入口/装配/中枢 |
| 零依赖纯叶子 | 13 个 | 单职责自包含 |
| 零被依赖 | 仅 `app.js` | 入口正确 |

**三层分离示例**：`chat.js`（组件）→ `chat-engine.js`（规则逻辑，纯函数）→ `chat-knowledge.js`（数据）；`quiz` / `heatmap` 同构。

## 六、已知取舍

- **`pages.js` 是"胖控制器"**：一个文件承担 6 页面初始化 + 点赞 + 留言 + 分页 + 详情渲染。功能上按注释分节、属可接受范围；若继续膨胀再考虑按页面拆分（受 `?v=` 工具链平铺约束，拆分方案需同步改 `bump-version.js`/`audit.js` 支持递归）。
- **`action-delegate.js` 是耦合集中点**：import 9 个模块。这是 data-action 委托模式的必然代价（中枢只派发不实现）；增删模块时需同步维护其 switch。
- **js/ 保持平铺**：缓存破击工具链（`bump-version.js` 的单段 import 正则、`audit.js` 的非递归扫描）依赖平铺布局；拆子目录会导致 `?v=` 漏刷新、模块被浏览器缓存旧版本。
